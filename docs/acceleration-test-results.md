# CPU / GPU 加速实测

## 结论

CPU 模板识别正常，GPU 通过 AMD OpenCL 实际参与计算，但本机测试的单模板识别没有获得速度收益，建议优先使用 CPU。CUDA 路径在当前环境不可用。

硬件和软件：AMD Radeon (TM) Graphics，驱动 30.0.13036.2；OpenCL 设备 gfx90c、OpenCL 2.0 AMD-APP (3302.6)；OpenCV 5.0.0，CPU 优化开启、线程数 12，CUDA 设备数 0，未提供 CUDA 模板匹配器。

## 结果与耗时

固定种子构造彩色图，并从中截取已知位置的模板。每种模式预热 3 次、测量 15 次，取中位数；同一个工作线程按 CPU → GPU → CPU 顺序复用，结果包含匹配结果读回与 CPU 候选点处理。下表使用预先转好的灰度输入，与生产识别重复使用灰度图的方式相符。CPU 两列为 GPU 前后的对照。

| 图像尺寸 | 模板尺寸 | CPU 前 / ms | OpenCL / ms | CPU 后 / ms |
| --- | --- | ---: | ---: | ---: |
| 320×480 | 12×12 | 3.624 | 6.109 | 4.189 |
| 320×480 | 40×40 | 4.346 | 14.957 | 4.004 |
| 720×1280 | 80×80 | 26.297 | 44.000 | 25.606 |
| 1116×2480 | 120×80 | 76.684 | 108.738 | 74.012 |

全部模式均命中相同坐标，GPU 目标分数均超过 0.99。CPU 与 GPU 有浮点误差，整张得分图的最大绝对差在本次样本中不超过约 0.0032；临界阈值不应要求逐位相同。

耗时不包含 ADB 截图、USB/Wi-Fi 延迟、设备点击、等待或投屏。颜色输入总流程与纯匹配耗时另见脚本输出。第一次初始化和编译不计入上述预热后的中位数。测试期间 OpenCV 提示临时目录磁盘缓存写入失败，因此结果属于当前缓存环境，不能直接外推到其他驱动或设备。

## GPU 使用证据

对同一个 Python 识别进程进行 Windows GPU Engine 计数器采样。工作负载为 1116×2480 灰度图、120×80 模板，连续计算 CPU → GPU → CPU，每阶段约 10 秒，统计时排除首尾各 1 秒。

| 阶段 | 完成匹配次数 | 中间采样数 | 该进程 GPU 引擎利用率合计均值 / 峰值 | 活跃引擎 |
| --- | ---: | ---: | --- | --- |
| CPU | 199 | 26 | 0% / 0% | 无 |
| GPU / OpenCL | 90 | 26 | 71.1% / 78% | Compute 1、Copy |
| CPU | 191 | 27 | 0% / 0% | 无 |

计数器按实际 Python 子进程 PID 过滤，表中的值是该进程引擎利用率之和，不等同于显卡总体占用或每个算子的 GPU 覆盖率。该结果证明测试时存在 GPU 计算活动；OpenCV 仍可能对个别内部操作透明回退 CPU。

## 本轮修复

- OpenCL 探测同时检查启用状态、GPU 设备类型、可用性和编译能力，避免仅有 OpenCL 平台或 UMat 的 CPU 回退被误报为 GPU。
- 探测使用非恒定图像和已知模板位置，不再依赖全零图自匹配的退化结果。
- 在实际引擎工作线程初始化加速模式；每次 OpenCL 匹配在执行线程确认上下文已启用。CPU 匹配明确禁用该线程 OpenCL。
- Python 层 GPU 匹配抛出错误时，输出回退日志并将当前模式降为 CPU，避免保留错误的 GPU 状态并重复尝试故障后端。
- 增加禁用上下文、CPU OpenCL 设备、执行线程初始化及故障回退回归测试。后端完整测试 215 项通过；设置 API 的 CPU → GPU → CPU 切换也在临时配置中通过。

OpenCV 的透明内部回退不会全部向 Python 抛错，因此“GPU 模式”仍应理解为优先尝试 GPU，而非保证全部操作都在 GPU 上。此次没有修改用户持久配置，也没有执行设备触控；尝试读取手机截图时设备不可用，性能结果全部来自可复现的合成图。

## 复测

在仓库根目录运行：

```powershell
.venv\Scripts\python.exe scripts/check_acceleration.py --samples 15 --output web/artifacts/acceleration-check.json
```

已连接并授权手机时，可增加 `--serial 10.0.35.91:5555`，脚本只抓取一次截图、在内存取模板，不保存手机图像、不点击或滑动、不修改配置。设备离线时在结果中说明，并继续合成图测试。

原始结果位于本机被忽略的 `web/artifacts/` 目录；此文档和复测脚本可纳入源码。修复生效需重启项目后端。
