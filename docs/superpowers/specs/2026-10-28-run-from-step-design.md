# 从指定步骤执行到流程末尾

日期：2026-10-28
状态：待确认

## 目标

在画布上选中任意**主流程步骤**后，可以直接从该步骤开始，按当前顺序一直执行到本次流程末尾。用于前缀步骤已经成功、只需要重跑后半段的场景，例如设备已经进入目标界面，只想重跑识别和点击步骤。

## 非目标

- 不实现“只执行单个步骤”。
- 不支持从模板分支节点开始；分支只能在父步骤命中后执行。
- 不改变顶部“运行”按钮的完整运行语义。
- 不在前端实现第二套执行逻辑，也不把起始步骤写入 `config.json`。
- 不改变运行快照、WebSocket 推送、停止和并发互斥规则。

## 已确认的行为

- 起点必须是当前预设中启用中的主流程步骤；否则拒绝并提示。
- 起点之前的步骤不执行。依赖检查把起点之前的步骤视为已满足，避免起点因为前置依赖未运行而被跳过。
- 从起点到末尾只执行一次，不套用预设的 `loop_count`；`end_loop` 只结束这次后缀执行。这样 `loop_count=0` 也不会因为从中间启动而无限循环。
- 返回边或 `jump_to` 指向起点之前的步骤时忽略并记录日志；指向起点及之后的返回边保持现有语义。
- 子预设（`run_preset`）和模板分支仍从各自第一步开始执行。
- 步骤编号和 `step_index` 保持原顺序（例如从 `8/10` 开始显示）；`step_count` 仍是本次预设的启用步骤总数。
- 日志增加一行“从步骤 X 开始执行（跳过前 N 个启用步骤）”。
- 运行状态、节点高亮、日志、停止和错误处理沿用现有链路。

## 方案

### A. 引擎原生起点（选用）

`POST /api/run` 增加可选的 `start_step_id`；`RuntimeManager.start` 校验后把起点写入 `RuntimeContext`；`StepEngine` 在根 frame 从该步骤开始执行，并把起点之前的启用步骤加入“视为已完成”集合。

- 优点：只有一套执行模型；依赖、返回边、日志、状态和 WebSocket 都复用现有实现；API 向后兼容。
- 代价：引擎需要处理起点、依赖假定和跨起点返回边，测试覆盖面增加。

### B. 运行前裁剪预设（未选用）

后端复制一份只保留起点及之后步骤的 `Preset` 再运行。

- 优点：引擎改动小。
- 代价：步骤编号、返回边、依赖和循环语义都要另行处理，容易形成第二套执行规则。

## 实现要点

### 后端

- `model_automation/engine.py`
  - `RuntimeContext` 增加可选 `start_step_id`，放在字段末尾，避免破坏现有位置参数。
  - `StepEngine.run` 读取根 context 的起点后清空 frame context，确保子预设和分支不会继承起点。
  - `_run` 从起点索引开始；起点之前的步骤视为已满足；本次后缀固定只跑一轮；跨起点返回目标忽略并记录日志。
- `web_server/runtime.py`
  - `RuntimeManager.start(preset_id, start_step_id=None)` 在既有运行互斥和快照流程内校验起点；把起点写入 `RuntimeContext`。
  - 起点不存在、属于分支或已停用时抛出 `ValueError`。
- `web_server/app.py`
  - `POST /api/run` 接受可选字符串 `start_step_id`；非法值返回 400，沿用现有 409/503 错误映射。

### 前端

- `web/src/api/run.js`：`startRun` 可选传入 `start_step_id`，未提供时不改变现有请求体。
- `web/src/stores/runStore.js`：`start(presetId, startStepId)` 可选转发；正常运行仍只传一个参数。
- 新增 `web/src/composables/useWorkflowRun.js`：集中设备检查、脏配置保存、起点校验和 `runStore.start` 调用；顶部运行按钮、节点按钮和右键菜单共用一份“准备中”状态，避免重复准备逻辑。
- `web/src/components/nodes/StepNode.vue`：悬停操作区增加 ▶ 按钮，标题“从此步骤运行”；停用步骤禁用；运行中、只读、保存中不显示操作区。
- `web/src/components/FlowCanvas.vue`：步骤右键菜单增加“从此步骤运行”；分支节点不显示该入口；点击后关闭菜单并调用同一组合式函数。
- `web/src/components/editors/PresetToolbar.vue`：改用组合式函数，顶部“运行”行为不变。

## 测试

- 引擎：从中间步骤执行后缀；起点前的依赖视为满足；停用的前缀不阻塞；`loop_count > 1` 和 `0` 都只跑一次；跨起点返回被忽略；起点后的返回仍生效；步骤事件保留原始编号。
- 运行时/API：`start_step_id` 透传、非法/停用/分支起点返回 400、原有完整运行不变。
- 前端：`runStore.start` 参数转发；组合式函数的设备检查、自动保存和起点校验；`StepNode` 按钮；右键菜单入口及分支隐藏。
- 回归：后端完整测试、前端 `npm test`、`npm run build`。

## 风险与边界

- 把前缀视为已满足是产品决定，日志会明确写出，避免用户误以为前缀刚刚执行过。
- 跨起点返回被忽略可能和完整运行不同，同样通过日志提示。
- 分支节点没有入口是明确限制；后续如有需要，再单独设计“从分支步骤开始”。
- 后缀只跑一次是为了避免无限循环，和顶部完整运行的循环语义不同；按钮标题和日志会说明。
